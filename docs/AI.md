# Використання AI-інструментів

Відповідно до п. 10 вимог: AI-інструменти дозволені, але кожен згенерований фрагмент потрібно вміти пояснити на захисті.

## Інструменти

| Інструмент | Для чого використано |
|---|---|
| **Claude Code** (Anthropic, модель Claude Opus) у VS Code | Генерація документації (ТЗ, UX, дизайн-система), верстка, CSS, JavaScript, React-компоненти, Express API, тести, скрипти перевірки, пошук і виправлення помилок |
| **Lighthouse**, **W3C Nu Validator** | Автоматичний аудит (не AI, але використовувались агентом для перевірки результату) |

## Як відбувалась робота

1. Агенту дано скриншоти завдання на практику й тему (варіант 2: ветеринарна клініка, запис із вибором лікаря).
2. Робота велась поетапно, за практичними роботами ПР 1 → ПР 10; кожна логічна частина — окремий коміт у форматі `feat:` / `fix:` / `docs:` / `test:` / `perf:`.
3. Кожен етап перевірявся автоматично: валідатор W3C, скриншоти в headless-браузері на 360 / 1280 px, автотести API, e2e-сценарії, Lighthouse.

## Що довелося виправляти

Помилки в коді, згенерованому AI, знаходились саме завдяки перевіркам, а не «з першого разу»:

| Проблема | Як виявлено | Причина та виправлення |
|---|---|---|
| React-сторінка падала при переході між маршрутами: `destroy is not a function` | e2e-сценарій у браузері | Ефект `useEffect(() => window.scrollTo(0, 0))` неявно повертав результат `scrollTo`. У нових браузерах це Promise, а React вважає повернене значення функцією очищення. Виправлено фігурними дужками в тілі ефекту |
| Застарілі правила React 19 для ref-колбеків | Аналіз попереднього дефекту | `ref={(el) => (x = el)}` теж повертає значення; переписано без повернення |
| Попередження лінтера: `setState` в ефекті, нечиста функція в рендері | `oxlint` | Стан меню «прив'язано» до сторінки замість ефекту; дата за замовчуванням обчислюється, а не встановлюється в ефекті; рік у футері винесено в константу |
| Нумерація «1. 2.» у хлібних крихтах, розтягнутий бейдж, зайвий відступ на десктопі | Скриншоти сторінок | Виправлено CSS (`list-style`, `align-self`, специфічність медіазапиту) |
| Конфлікт CSS-класу `.step` між головною та формою запису | Огляд стилів | Клас форми перейменовано на `.form-step` |
| `hidden` не ховав елементи з `display: flex` | e2e-сценарій | Глобальне правило `[hidden] { display: none !important }` |
| 7 попереджень W3C «role=list is unnecessary» | W3C Validator | Прибрано зайві ролі, скидання стилів списків через клас |
| SEO 91–92 (немає `robots.txt`), CLS 0.18 на сторінці запису, LCP 2.7 s | Lighthouse | `robots.txt` і `sitemap.xml`, скелетон резервує висоту, локальний шрифт, каталоги в основному бандлі |
| Скрипти Python не виконувались (на Windows `python` — заглушка Microsoft Store) | Перевірка результату | Скрипти переписано на Node.js |
| Git Bash перетворював `/vetdim-clinic/` на шлях Windows під час локальної збірки | Симуляція GitHub Pages | `MSYS_NO_PATHCONV=1` (у CI на Linux цієї проблеми немає) |

## Що я маю вміти пояснити (план підготовки до захисту)

- **HTML**: навіщо `header/nav/main/article/aside`, skip-link, `aria-current`, `aria-pressed`, `aria-describedby`.
- **CSS**: токени в `:root`, темна тема через `[data-theme="dark"]`, mobile-first медіазапити, `clamp()`, Grid/Flexbox у картках, «розтягнуте посилання» (`::after` з `inset: 0`).
- **JavaScript**: ES-модулі й динамічний `import()`, делегування подій, debounce у пошуку, `escapeHtml` проти XSS, валідація через об'єкт правил.
- **React**: `useState`, `useEffect` (і чому ефект не повинен нічого повертати, крім функції), власні хуки `useFetch`/`useTheme`, `useMemo`, `useDeferredValue`, `useSearchParams`, `lazy` + `Suspense`.
- **Express**: маршрутизатори, middleware, статуси 201/204/400/404/409, централізований обробник помилок, чому валідація дублюється на сервері.
- **PWA**: manifest, стратегії кешування service worker (network-first / cache-first).
- **Деплой**: GitHub Actions → Pages, `404.html` для маршрутів SPA, змінна `VITE_API_URL`, CORS.

## Висновок

AI суттєво прискорив роботу, але не замінив перевірку: усі знайдені дефекти виявлено інструментами тестування (лінтер, валідатор, e2e, Lighthouse) і виправлено окремими комітами. Найцінніший досвід — дефект із `scrollTo`: він показав, що навіть «очевидний» код залежить від версій браузера й бібліотек.
