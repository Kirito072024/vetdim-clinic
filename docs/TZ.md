# Технічне завдання — веб-сайт ветеринарної клініки «ВетДім»

## 1. Загальні відомості

| Пункт | Значення |
|---|---|
| Назва проєкту | «ВетДім» — сайт ветеринарної клініки |
| Тип | Багатосторінковий SPA (React + Vite) з власним REST API (Node.js + Express) |
| Ключові сутності | **Лікар**, **Послуга**, **Запис на прийом** |
| Цільова дія | Запис на прийом з вибором лікаря |
| Репозиторій | https://github.com/Kirito072024/vetdim-clinic |

## 2. Мета та актуальність

Власники тварин часто записуються до ветеринара телефоном: доводиться чекати на лінії, вони не знають, який лікар має потрібну спеціалізацію, і не бачать вільного часу. Сайт «ВетДім» дає змогу:

- переглянути послуги клініки та орієнтовні ціни;
- ознайомитися з лікарями (спеціалізація, досвід, графік);
- **записатися онлайн до конкретного лікаря** на вільний час без дзвінка.

## 3. Цільова аудиторія

- Власники кішок і собак віком 20–45 років, які користуються переважно смартфоном.
- Люди старшого віку, які записують тварину до «свого» лікаря та користуються ПК.

Детальніше про персони — у [UX.md](UX.md).

## 4. Структура сайту (сторінки)

| № | Сторінка | URL | Призначення |
|---|---|---|---|
| 1 | Головна | `/` | Переваги клініки, популярні послуги, лікарі, CTA «Записатися» |
| 2 | Лікарі (каталог) | `/doctors` | Список лікарів, фільтр за спеціалізацією, пошук |
| 3 | Сторінка лікаря | `/doctors/:id` | Фото, спеціалізація, досвід, послуги, графік, кнопка запису |
| 4 | Послуги (каталог) | `/services` | Список послуг з цінами, фільтр за категорією |
| 5 | Запис на прийом (форма) | `/booking` | Вибір послуги → лікаря → дати й часу → дані власника і тварини |
| 6 | Контакти | `/contacts` | Адреса, телефон, графік роботи, карта, форма зворотного зв'язку |
| 7 | 404 | `*` | Сторінку не знайдено |

Обов'язковий мінімум за вимогами — 4 сторінки (головна, каталог, деталі, форма); заплановано 6 + 404.

## 5. Функціональні вимоги

### 5.1 Каталог лікарів
- FR-1. Відображення карток лікарів: фото, ПІБ, спеціалізація, стаж.
- FR-2. Фільтр за спеціалізацією (терапевт, хірург, дерматолог, стоматолог, офтальмолог).
- FR-3. Пошук за ім'ям.

### 5.2 Сторінка лікаря
- FR-4. Детальна інформація: освіта, досвід, перелік послуг, дні прийому.
- FR-5. Кнопка «Записатися до цього лікаря» відкриває форму з уже обраним лікарем.

### 5.3 Послуги
- FR-6. Список послуг: назва, категорія, тривалість, ціна «від».
- FR-7. Перехід від послуги до запису з уже обраною послугою.

### 5.4 Запис на прийом
- FR-8. Покрокова форма: послуга → лікар (лише ті, хто надає цю послугу) → дата → вільний час.
- FR-9. Дані власника: ім'я, телефон (+380…), email (необов'язково).
- FR-10. Дані тварини: кличка, вид (кіт / пес / інше), вік, коментар (скарги).
- FR-11. Валідація на клієнті (формат телефону, обов'язкові поля, дата не в минулому) і на сервері.
- FR-12. Після успішного запису — екран підтвердження з номером запису.
- FR-13. Зайнятий час недоступний для вибору (сервер перевіряє конфлікти).

### 5.5 Загальне
- FR-14. Адаптивне меню (бургер на мобільних).
- FR-15. Світла й темна тема з перемикачем.
- FR-16. Форма зворотного зв'язку на сторінці контактів.

## 6. REST API (Node.js + Express)

| Метод | Ендпоінт | Опис |
|---|---|---|
| GET | `/api/doctors` | Список лікарів (`?specialty=`, `?q=`) |
| GET | `/api/doctors/:id` | Деталі лікаря |
| GET | `/api/doctors/:id/slots?date=YYYY-MM-DD` | Вільні слоти лікаря на дату |
| GET | `/api/services` | Список послуг (`?category=`) |
| GET | `/api/services/:id` | Деталі послуги |
| GET | `/api/appointments` | Список записів (адмін / демо) |
| POST | `/api/appointments` | Створити запис |
| PUT | `/api/appointments/:id` | Змінити запис |
| DELETE | `/api/appointments/:id` | Скасувати запис |
| POST | `/api/feedback` | Повідомлення з форми контактів |

Зберігання даних — JSON-файл (або SQLite) на сервері.

## 7. Нефункціональні вимоги

- NFR-1. Mobile-first, коректне відображення на 360, 768 і 1280 px.
- NFR-2. Lighthouse (mobile): Performance, Accessibility, Best Practices, SEO — кожен ≥ 90.
- NFR-3. Семантичний HTML5, без помилок W3C-валідатора.
- NFR-4. Доступність: контраст за WCAG AA, `alt` для зображень, керування з клавіатури, `label` для полів.
- NFR-5. Підтримка останніх версій Chrome, Firefox, Safari та Edge.
- NFR-6. Інтерфейс українською мовою.

## 10. Критерії приймання

- Сайт опубліковано, автодеплой із `main` працює.
- Користувач може пройти сценарій «вибрати лікаря → записатися» на мобільному та на десктопі.
- Записи зберігаються через API і не допускають подвійного бронювання слота.
- Lighthouse ≥ 90 за всіма чотирма категоріями (mobile).
